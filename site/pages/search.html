Count a legal move tree

Perft counts leaf positions after a fixed number of plies. It is a move-generation check, not a playing-strength benchmark. The initial position has 20, 400, 8,902, and 197,281 nodes at depths 1 through 4.

Perft(0) returns 1. A negative depth returns 0. Traversal restores the root position before returning.

Move buffers belong to the caller

SearchBoard.LegalMoves(dst) generates legal moves into the supplied storage. A buffer with enough capacity avoids a move-list allocation. Keep a separate buffer at each recursion level so child generation cannot overwrite the parent's moves.

SearchBoard.MakeMove assumes a legal move and must be paired with UndoMove in reverse order using the same move value. The board maintains piece placement and move state; it does not refresh repetition, PGN, checkmate, or draw status while traversing.

Use Game.TryMove* for a real game. Game.MakeMoveFast / UndoMoveFast are lower-level alternatives that also skip game-history bookkeeping. Do not mix fast traversal with application status queries.

Static exchange evaluation

Game.SEE(from, to) estimates the material result of a swap sequence on a square. It is useful for move ordering and capture heuristics, not a full search or position evaluation. It uses the occupancy of the exchange sequence but a snapshot of pins; use the documented assumptions when integrating it into an engine.

The package supplies rules and traversal primitives, not an engine protocol client, evaluation function, transposition table, or search algorithm. PositionKey() is available for your own hash tables.

Keep allocations out of the loop

  • Reuse a SearchBoard and one move buffer per depth.
  • Use move values in the search loop. Format SAN or FEN at presentation boundaries.
  • Use full Game instances where repetition and game state matter.
  • Measure your own workload with -benchmem; cold setup and warmed traversal have different allocation costs.
