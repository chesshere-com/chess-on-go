Use text formats for interoperability and binary data for same-version position persistence. Each format preserves a different part of the game.

FEN: one position

NewGameFromFEN constructs a standard game. LoadFEN validates the input before replacing an existing game's state; FEN exports it. Load variant positions with LoadFENWithVariant.

game, err := chessongo.NewGameFromFEN(
    "rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq e3 0 1",
)
if err != nil {
    return err
}
fmt.Println(game.FEN())

Validation checks board shape, kings, pawns on promotion ranks, castling metadata, en-passant fields, counters, and position legality. An en-passant target may be present without a legal capture; repetition hashing includes it only when a legal capture exists.

var fenErr *chessongo.FENError
if errors.Is(err, chessongo.ErrInvalidFEN) {
    // Report invalid position input.
}
if errors.As(err, &fenErr) {
    fmt.Println(fenErr.Field)
}

FEN has no move history or prior repetition counts. Loading it starts a new history. If your app stores prior same-version position keys, call SeedPositionHistory(priorKeys) after loading; exclude the current position because loading already records it. Move counters saturate at the platform's maximum int instead of wrapping.

PGN: a played main line

LoadPGN applies the main line, accepts attached move numbers, tag pairs, setup FEN, results, comments, NAGs, and nested variations. Comments, NAGs, and variations are skipped, not preserved. Use PGN(), PGNTags(), and PGNResult() for export.

Custom starting positions and supported variants produce setup tags. Result tags and movetext must agree; contradictory terminal results, unknown variants, and moves after a result are rejected.

Need to edit and round-trip annotated variation trees? corentings/chess has a broader PGN model. chess-on-go focuses on playing and exporting the main line. See the capability comparison.

EPD: annotated positions

ParseEPD accepts an EPD record: the first four FEN fields followed by semicolon-delimited operations. Quoted operands may contain semicolons and escaped quotes. LoadEPDRecords reads multiple records from an io.Reader.

Binary: current state and repetition

MarshalBinary / UnmarshalBinary preserve the current board, active variant, variant counters, castling metadata, move counters, and repetition counts. They do not save the played PGN or the undo stack. Treat the format and position keys as same-version data; prefer FEN/PGN for stable interchange.

The decoder validates the position before replacing state. Encoding rejects counters or repetition values outside the format's unsigned 32-bit range.
